# Loop de Story Ralph

**Trigger:** Sempre que a tarefa mencionar Ralph, story, PRD, `scripts/.last-story`, `scripts/ralph.sh`, `scripts/implement.sh`, `scripts/gate.sh`, ou quando o agente precisar continuar uma implementação já iniciada no projeto.

## O que fazer

Antes de editar código, recupere o estado da story:

1. Leia `scripts/.last-story` para identificar a story atual, se existir.
2. Consulte `scripts/prd.json` para entender escopo, aceite e arquivos prováveis.
3. Verifique `git status --short` para separar mudanças existentes das suas.
4. Inspecione apenas os arquivos diretamente relacionados à story.

Implemente a menor mudança que satisfaz a story:

1. Preserve a arquitetura simples do projeto: funções diretas, sem camadas novas.
2. Mantenha a mudança dentro do diretório da área afetada (`iot/`, `ml/`, `api/` ou `mobile/`).
3. Adicione ou ajuste testes próximos ao código alterado.
4. Não reescreva arquivos não relacionados para “limpar” estilo.

Ao finalizar, rode o gate apropriado usando o script do projeto:

```bash
bash scripts/gate.sh <arquivo_ou_diretorio_alterado>
```

Se o gate falhar:

1. Leia o erro.
2. Corrija a causa mínima.
3. Rode o mesmo gate novamente.
4. Só reporte conclusão quando o gate passar.

Na resposta final, informe objetivamente:

- story/área atendida;
- arquivos principais alterados;
- resultado do gate (`gate: OK` ou erro restante).

## O que evitar

- Começar implementação sem confirmar qual story está ativa.
- Assumir escopo amplo quando a story pede uma entrega pequena.
- Criar abstrações, classes, repositórios ou camadas novas sem necessidade explícita.
- Rodar apenas testes manuais e declarar conclusão sem `scripts/gate.sh`.
- Reverter ou sobrescrever mudanças existentes que não pertencem à story atual.
- Corrigir falhas do gate com mudanças amplas que alterem comportamento fora do escopo.
